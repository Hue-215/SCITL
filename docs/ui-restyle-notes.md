# UIの見た目の改修: 検討の経緯と残課題

2026年9月に、画面の見た目(配色の使い方・奥行き・角丸・一部の配置)を見直した記録。
確定した方針は `spec/rebuild/ui.md` 2節「塗りと奥行き」と6節に移してあり、この文書は
**なぜその形になったか**と、**実機での調整で詰める項目**を残すためのものである。
方針と食い違う場合は `ui.md` を正とする。

検討にはclaude.ai上のデザインキャンバス(非公開。所有者のみ閲覧可)を使った。
https://claude.ai/artifact/7TF9Mx5dGzr3LSty9eRy8D
各案はそこに実物大のモックとして残っている。以下の記号(A〜H)はキャンバス上の名前と対応する。

## 出発点

- 基本はフラットデザインを維持し、角丸とグラデーションはほぼ使わない
- Aero以前(Windows 9x〜7)の意匠を、アクセントとして取り入れたい
- スマートフォン(OLED)を意識し、背景・線・アクセントの3色を基調にしたダーク寄りの方向も検討したい

## 検討した案と判断

| 案 | 内容 | 判断 |
|---|---|---|
| A | 現行(比較の基準)。ダーク/ライト | 基準として残した |
| B | フラット+Classic(〜2000年頃)のベベル。ボタン・入力欄・スクロールバーだけ立体 | 方向性の参考に留めた |
| C | フラット+Aeroの縁取り(暗い外線と明るい内線、フォーカスの光) | 「光る枠」を下線に置き換える方向へ発展(F) |
| D・E | OLED向けの3色(黒・線・アクセント)。Eは二重線と硬い影を追加 | **保留**。ライトテーマを先に詰めることにした |
| F | 現行ライト+角丸の吹き出し+下線。のちにグレーの塗り+下向きの影へ | 「図らずもニューモーフィズム風味で、ノスタルジーが良い」という評価。Hの原型 |
| G | 単色+アクセントのニューモーフィズム(部品と背景が同じ色) | **不採用**。部品の輪郭が影の濃淡だけになり、押せる場所が直感的に分からない |
| H | 背景1色・部品は塗りで区別・奥行きはライトで影/ダークで光 | **採用**。実装に移した |

Gで分かったのは、目指している形が「**背景は画面全体で1色、部品は塗りで輪郭を作り、影で浮かせる・沈ませる**」
の両立だということ。色(塗り)と影に別々の役目を持たせ、影は補助に留める。これがHの骨格になった。

## Hで決めたこと

### 塗りは3段で固定

背景・浮いた部品・沈んだ部品(選択中)の3段。沈んだ部品は、へこみが見えるよう背景に近い
薄い塗りにした(ライトで背景98%・沈み94%・浮き90%)。明るさの順と浮き沈みの順は一致しないが、
一致させないほうが凹凸がはっきり見える。

ダークは現行の値(9%・14%・21%)がそのまま同じ関係になっていたため、変えていない。

### 奥行きの意味

- 浮き=押せる。沈み=値を入れる所、または選ばれている。持ち上げ(浮きより弱い)=押せない面(吹き出し)
- ダークは影の代わりに縁の光で表す(浮きは上辺、沈みは下辺。Classicのベベルと同じ理屈)

### 影の値(ライト)

モックで何度か往復して決めた値。実装では `theme.ts` の `buildElevation` にある。

| 名前 | 値 | 調整の経緯 |
|---|---|---|
| 浮き | `0 2px 4px -1px`・不透明度19% | 当初25%。「ボタンがやや濃い」で下げた |
| 沈み | `inset 0 2px 4px -2px`・34% + `inset 0 1px 1px`・10% | 「凹み感が薄い」で一度深くし(45%)、設定画面で入力欄が並ぶとうるさいため中間に戻した |
| 持ち上げ | `0 2px 5px -1px`・24% | 当初は浮きより弱い20%。「吹き出しの浮きが弱い」で上げた |
| フォーカス | `0 0 8px`・アクセント色45% | Aero案のフォーカスの光を残した |

### 個別の部品

- **吹き出しだけ角丸**。半径は近い側マージンの半分(直角だと尖って見えるため)
- **サイドバーの選択中の項目**は、背景色の塗り替えではなく「沈み」で示す。下線も試したが、塗りと影があれば
  下線は見えても見えなくても変わらなかったため外した
- **左カラムの項目は押せることが分かりにくい**ため、ホバーで浮くようにした。スマートフォンにはホバーが無いので、
  ホバーは `@media (hover: hover)` の中だけで効かせ、押した瞬間の沈みで反応を返す
- **タスクを追加・送信**は、濃い青の塗りだと影が塗りに溶けて見えなかった。ユーザーの吹き出しと同じ薄い青に
  変え、主ボタン専用の影を作らずに済ませた
- **タスクを追加は左カラムの下端に接する**形(現行の配置)。送信とそろえる・下端から16px・4pxも比べたが、
  下端に接するほうが右カラムと明確に区別でき、かえって違和感がなかった
- **モデル選択**は、入力欄の中・入力欄の上・見出しの横も比べた。入力欄の中は入力欄が高くなるため不採用。
  legacyでは入力欄の左下/右下でも目立っていなかったため、その配置で、背景なしの小さな文字にした。
  入力欄の幅(添付と送信の間)にそろえ、入力欄との間とウインドウ下端との間を等しくしている(`--compose-bottom-gap`)
- **チェックボックス**は沈んだ箱にチェックの線を描く形(Classic期と同じ形)。ラジオボタンはネイティブのまま
- **プロバイダーのカード**は枠線だけで塗らない。部品と同じ灰色を塗ると、中のボタンと塗りが重なり、
  Gと同じ「影だけで輪郭を作る」形になるため
- **プルダウン(表示言語)**は、押すと一覧が開くので「浮き」に寄せた

## 実機調整で詰める項目

`ui.md` 7節の手順どおり、クラウド環境ではアプリを起動できないため、静的ハーネスでの寸法の実測
(Chromium)までしか行っていない。以下は実機(WebKitGTK)で確かめる。

- **WebKitGTKでの描画**: チェックボックスへの `appearance: none` と `::before`、`inset` を含む `box-shadow`、
  `:is()`、`display: contents` を付けた `<form>`(入力欄の格子)、`@media (hover: hover)`
- **ダークモードの縁の光**: モックの段階からかなり控えめで、特に塗りのあるボタンでは見えにくい。
  ライトの調整を反映していないので、強さを実物で決める
- **アクセント色の役割**: 塗りに `primary` を使う場所が無くなり、残るのはフォーカスの光とリンクの文字色だけ。
  `theme.ts` の `primary` の明度を見直すかどうか
- **モデル選択の上下の余白**(`.dropdown-toggle` の0.125rem): トークンに無い値で、1箇所限りの直値として置いた。
  4px(`--space-1`)にそろえるなら、行が4px高くなる
- **ダイアログ・ドロップダウンの一覧・チップ**: 塗りの整理に合わせて背景だけ直した。見た目はまだ詰めていない
- **OLED向けの3色案(D・E)**: 保留中。採用するなら、Hのダークとは別のテーマとして設計することになる
