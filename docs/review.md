# レビュー・テストの指摘の一時置き場

コード全体のレビューやブラックボックステストで出た指摘を、Issueにするまで置いておく場所。
方針の文書ではなく、作業項目の正本でもない(正本はGitHub Issues。CLAUDE.md「情報の置き場所」)。

## このファイルの扱い

- **検証済みの指摘はIssueにする。** 細かい修正で、同じ箇所・同じ種類のものは1つのIssueにまとめる
- **未検証の指摘は、検証してからIssueにする。** 検証はコードを読むか、実機(`scitl-debug-cli`と疑似API。
  手順は`.claude/blackbox-test.md`)で再現して行う。再現しなかったもの・仕様どおりだったものは、
  Issueにせずに消す
- **Issueにした指摘は、このファイルから消す。** どのIssueになったかの対応表も残さない
  (Issueの本文に出所を書く)
- 既にIssueのあるものは、ここに書かずにそのIssueへ足す
- ここに残るのは、まだIssueにしていない指摘と、Issueにならない記録(決まったこと・まだ試していない領域)だけ

## 決まったこと

- **MPL-2.0は許容する**(ファイル単位の弱いコピーレフトで、SCITL自身のコードのライセンスを縛らない)。
  実行バイナリに入るのは`option-ext`(`dirs`経由。Tauri自身も使う)だけで、`selectors`・`cssparser`・
  `dtoa-short`はビルド時のみ。npmのMPL-2.0は開発依存の`lightningcss`だけ。GPL・LGPL・AGPLは無い。
  同梱フォントはSIL OFL 1.1(同梱は可、フォント自体はOFLのまま)。ライセンスはMIT予定なので、
  コピーレフトのライブラリは使わない

## まだIssueにしていない指摘

なし。

## ブラックボックステストでまだ試していない領域

テストを途中で止めたか、道具の都合で試せなかった領域(2026-10-01、`1e7f749`時点)。

- GUIでしか見えないもの: 40文字を超えるタイトルや不可視の書式文字の表示、視覚入力に対応しないモデルへ画像を付けたときの警告、
  入力欄でのAPIキーの改行の扱い
- `scitl-debug-cli`に操作が無いもの: 発言の削除・編集、削除したタスクの復元、思考設定(thinking・effort)の変更、
  モデルの能力(画像・思考・文脈長)の上書き、添付付きの発言の`chat preview`
- Sham_llmの都合で試せなかったもの: 数万文字の同じ文字の連続や20万文字のツール説明を含むリクエスト(Sham_llmがCPUを使い切って
  応答しなくなる。上限ちょうどのテキスト添付、数万文字の日本語のタイトル・説明、ツール300個を公開した実ターンが未実施)、
  定義に無いツール名の呼び出し・本文もツールも無い応答(`reply`が差し戻される)、応答の打ち切り(`max_tokens`等)・拒否
- Anthropic形式・Gemini形式の残り: 添付・画像の表れ方(Gemini形式へ画像を実際に送る経路)、外部ツールの公開、
  Gemini形式の実際のAPIとの応答形式の差
- 時間のかかるもの: `response_timeout_secs`の時間切れとその最中の作り直し
- MCPサーバーの残り: 削除後に資格情報ストアから秘密が消えるか(`secret-tool`が無く観察できなかった。`config.toml`からは消える)、
  異常なツール(空の名前・同名2件・`type: array`のスキーマ)をモデルが実際に呼んだときの渡り先、
  GUIでサーバープロセスがターンを跨いで保たれる場合の、クラッシュ後の次のターン
- GUIとCLIを同時に操作した場合の振る舞い
- その他: 30MBを超える添付と画像の枚数の上限、添付付きの発言がエラーになった場合の添付の残り方、
  書き出しで添付ファイルの実体が無い場合、`provider models`へのエラー(401・429・500)
- 試す必要が無くなったもの: ストリームの途中での切断(アプリは3方言とも非ストリーミングでリクエストする)
