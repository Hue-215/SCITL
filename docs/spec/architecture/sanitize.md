# 無害化

外部から来た文字列と自由入力を、どこへ出すときに何を掛けるかをまとめる(`../principles.md`
4節)。**無害化は出力先ごとに決める**。同じ文字列でも、モデルへ送るときと画面に出すときとでは
防ぐものが違う。一番強い処理を一律に掛けると、画面に `&lt;` が漏れたり、本文の絵文字が
壊れたりする。

- **保存するデータは書き換えない**。DB・設定・ツール一覧のキャッシュ・ツール実行記録は
  受け取ったままを持ち、出力先へ出す直前に掛ける。例外は次の4つだけ
  - 保存前の正規化。フィールドの値の形(1行か、空を許すか)を決めるもので、防御ではない
    (タイトルは`db::tasks`、工程の説明は`db::task_steps`。`../tools.md` 2節)。長さの上限を超える
    値は切らずに断る。タイトルとメモリの本文は描かれない文字もここで除き、メモリの本文はさらに重ねた
    異体字セレクタも除く(`../tools.md` 2節、`../data-model/tables.md` memories)
  - SCITL自身が組み立てる診断文字列(エラー文言)。長さの上限と秘密情報の伏せ字は保存より前に
    済ませる必要があるため、組み立てる時点で掛ける。ツールの失敗として`{"error": ...}`に
    載る場合は、画面向けに整えた形(省略の「…」を含む)のままモデルにも渡る
  - 外部ツールの結果の長さの上限(`mcp::to_result_value`)。モデルへ返す値と実行記録を同じ値から
    作るため、実行記録も上限で切った形で残る
  - モデルへ送った形の保存。送った形そのものを持つので無害化済みの形になる。モデル向けの無害化の
    規則を変えたら保存の形の版を上げる(`transcript.md`「前が変わる場面の扱い」)
- **識別子は書き換えない**。外部ツールの名前は受け取ったまま有効化の照合と呼び出しに使い、
  表示には別に作った写しを使う(モデル名も同じく、登録・選択・リクエストには受け取ったままの
  名前を使う)。書き換えた名前で照合すると、サーバー上の別のツールを
  呼びうる。モデルへ公開できるかの判定は`tools::external`(`exposed_name`・`is_exposable`)に置き、
  公開できないツールは有効にさせない
- 表に無い出力先を足すときは、先にこの表へ行を足す

端末への出力は、`scitl-cli`と`scitl-debug-cli`のコードが`scitl_cli::terminal`からだけ書く(clapが
自分で書くヘルプ・引数のエラーも受け取ってから通す)。coreが失敗にせず先へ進めたときの診断
(設定ファイルを読めない等)は、coreの唯一の診断の出口`diagnostics::report`が同じ処理を
掛けて書く。書き先は標準エラーで、Androidではlogcat(タグ`SCITL`、重さは`WARN`に固定)にする。
Androidの標準エラーも、taoが起動時にパイプへ付け替えてlogcat(タグ`RustStdoutStderr`)へ流す
(tao 0.35の`ndk_glue::create`で確認、2026-10)。ただ、パイプは別のスレッドが読むので、書いた直後に
プロセスが終わると取りこぼしうる。タグもほかのクレートの出力と混ざり、文書化された振る舞いでもないので、
診断はそちらに頼らない。panicの文言と依存のクレートが標準エラーへ書いたものは、`RustStdoutStderr`の
側に出る。logcatへはNDKの`liblog`を直に呼んで書き、実行時依存を
増やさないためクレート(`android_logger`等)は足さない。liblogは1件をおよそ4KBで黙って切るので、
長い診断は文字の途中で切らずに複数件に分けて書く。`log`・`tracing`は入れず、種類や重さでの
絞り込みは持たない。

## モデルへの出力(予約タグ)

予約タグは `scitl:` 名前空間のタグすべてとする。無害化した文字列は `llm::PromptText` で運ぶ。
`PromptText` は無害化を通すコンストラクタでしか作れず、発言列のユーザー発言・ツール結果は
この型の値しか受け取らない。ツールの定義(`ToolSchema`)はフィールドを外から書けず、
コンストラクタで無害化する(内部ツールは名前と説明をコードに書いた定数に限り、引数スキーマに
掛ける。外部ツールは説明と引数スキーマに掛ける)。経路を足したときの掛け漏れはコンパイルで
止まり、アダプタは取り出して送るだけで無害化を呼ばない。

**システムプロンプト(`ChatMessage::System`)だけは型で強制されない**(理由は下の箇条)。
自由入力は載せない(タスクのタイトル等は、ツール結果や操作の記録として発言列の側に載る)。
足す必要が出たら、組み立ての1箇所(`orchestration::system_prompt::build_system_prompt`)の
中で `PromptText` を通す。

| 経路 | 自由入力 | 生成 |
|---|---|---|
| ユーザー発言 | 本文 | `PromptText::user_message`(囲みの組み立てと一緒に行う) |
| 会話の外での操作の記録(`prompt-shape.md`「会話の外での操作の伝え方」) | タスクのタイトル・説明、工程の説明、捨てた試行でモデルが出した引数、外部ツールの名前と出力 | `PromptText::operations`(記録のJSONは`PromptText::json`と同じく直列化した全体に掛ける) |
| 同一ターン内のツール結果 | 内部ツールが返すタスク・工程・メモリ、外部ツールの出力 | `PromptText::json`(直列化した全体に掛ける) |
| 次ターン以降のツール結果(`../tools.md` 4節) | 内部ツールが返すタスク・工程・メモリ、外部ツールの出力 | `PromptText::json`(実行記録の保存値に、送る直前で掛ける) |
| システムプロンプトの変更の通知(`transcript.md`「前が変わる場面の扱い」) | 利用者が書いたプロンプト(システムプロンプトと同格の指示で、ユーザー発言ではない) | `PromptText`の生成時に全体に掛ける。システムプロンプト本体には掛けないが(下の箇条)、userの発言の中に置くのでユーザー発言の囲みを偽装できないようにする |
| 外部ツールの定義 | サーバーが書いた説明・引数スキーマ | `ToolSchema::external`(スキーマは直列化したJSON全体に掛けて読み直す) |
| 添付(`attachments.md`「モデルへの渡し方」) | ファイル名、テキストの本文 | `PromptText::user_message_with_attachments`(JSONに直列化した全体に掛ける) |

- 操作の記録・ツール結果・引数スキーマは**直列化したJSONの形のまま**掛ける。改行・引用符は
  JSONのエスケープで文字列値の中に閉じ込められるため、見出しや区切りを偽装できない。予約タグは
  文字列値の中でもタグとして読めるので、無害化を別に掛ける。JSONの構文に `<` は現れないため、
  置き換わるのは文字列値とキーの中身だけで、JSONとしての形は崩れない
- 引数スキーマのキー名や `enum` の値に予約タグがあると、モデルは `&lt;` の付いた値を送り、
  サーバーに拒否される。壊れたスキーマで機能が落ちるだけなので、安全側として受け入れる
- システムプロンプト全体には掛けない。ユーザーが設定した部分は書き手がシステムプロンプトの
  作者そのものであり、偽装する相手がいない。予約タグの読み方の説明は予約タグそのものを含む
- アシスタント発言には掛けない。モデル自身の出力であり、APIの役割(`role`)で
  ユーザー発言と区別されている。モデルには、形式の説明(`llm::user_message_format_note`)で
  `scitl:`で始まるタグを返信に書かないよう伝える。説明に無いタグも含めて禁じるのは、
  説明したタグだけを禁じると、モデルがそれに似せた別の名前のタグを書くことがあるため
- **防ぐのは、`<`のあとに任意の`/`と`scitl:`が続く形と、その見た目の似た形**(#174)。
  モデルは文字を意味で読むので、HTMLとしてはタグにならない形もタグとして読みうる
  - 照合は1文字ずつ互換分解(NFKC。`icu_normalizer`)で畳んでから、大文字小文字を問わずに行う。
    全角の`＜`・`／`・`ｓｃｉｔｌ`・`：`、小字形の`﹤`、数学用英字・丸囲みの英字などが畳まれる
  - 間の空白・制御文字と描かれない文字(`text::is_invisible_format`と異体字セレクタ)は読み飛ばす。
    `scitl:`の文字の間も読み飛ばすので、`< s c i t l :`のような本文も無害化される(余計に
    無害化しても、`<`が`&lt;`に見えるだけ)
  - 照合に使うだけで、置き換えるのは先頭の`<`(またはそれに畳まれる`＜`・`﹤`)だけ。本文は
    書き換えない。形式の説明で、構造はリテラルの`<`で始まるものだけで、`&lt;scitl:`は誰かが
    書いた本文であることを伝える
  - 照合の規則は`icu_normalizer`の持つUnicodeの版で決まる。版が上がると、新しく割り当てられた
    文字が畳まれるようになりうる(既にある文字の結果は、正規化の安定性の保証で変わらない)。
    保存の形の版(`FORM_VERSION`)を上げずに規則が広がるが、広がる向きは無害化が増える側だけ
  - **範囲外**: 畳まれない別の文字による偽装(キリル文字の`ѕ`、分数の斜線`⁄`等)と、描かれる
    文字を挟む形(点字の空白U+2800、結合記号)。JSONに直列化して掛ける経路(ツール結果・操作の
    記録等)では、文字列値の中の改行・タブ等の制御文字は`\n`・`\u0007`等のエスケープになり、
    読み飛ばす文字に当たらない。これらをモデルが構造と読み違えた場合の
    被害は、公開するツールの権限を絞ること(`../tools.md`)で抑える。この無害化があることを
    理由に、それ以外の対策を省いてはならない

## 画面への出力

- **Markdownの描画がHTMLの生成になる**: WebViewでは描画結果がそのままDOMになるので、
  **MarkdownからHTMLを生成する場合は必ずサニタイズを通す**(`../principles.md` 4節)
- Rust側で文字を除くのは、外部由来のラベルと診断文字列だけ。利用者はそれを見て判断を下す
  (どのツールを有効にするか、何が失敗したか)ため、見た目と中身が一致していることに価値がある
- モデル出力とユーザー発言は書き換えない。モデル出力を操れる相手は見える文字で何でも書けるため、
  見えない文字を除いて防げるのは周りの表示への波及だけで、それは要素の境界で閉じ込めれば足りる。
  除くと、絵文字の結合に使うゼロ幅接合子などの正当な文字が壊れる
- 公開できる名前はASCIIの英数字・`_`・`-`に限られるため、表示用の写しが別のツールと同じに
  見えうるのは公開できないツールだけで、それは有効にできない

## 長さの上限と省略の印

省略の印は出力先で分ける。画面は「…」。保存値は印を付けない(上限は値の形の一部)。
モデル向けは英語の注記とし、何が省かれたかをモデルが読めるようにする(`prompt-shape.md`「モデルに渡す
固定文言は英語で書く」)。例外は外部ツールの説明で、画面と同じ形をモデルへ渡すので「…」になる(下記)。

外部ツールの説明は2,000文字で切り、引数スキーマが(直列化したJSONで)2,000文字を超える
ツールは公開しない(`tools::external`)。ツールの定義は毎ターン送るので、1件の巨大な定義が
会話を文脈長に収まらなくする。スキーマは引数ごとの説明・列挙・入れ子をいくらでも持てるので、
説明だけを切っても防御にならず、両方に上限を置く。説明はサーバーが書いた値で書き直せないので
切り、スキーマは切ると壊れるので断る。説明は、画面に出す形(`text::display_block`。描かれない文字を
除き、長さの上限で切る)をそのままモデルへ渡す(`tools::external::description_of`)。利用者が画面で読んで
有効にした説明と、モデルが受け取る説明を一致させ、画面に見えない指示を紛れ込ませないため。引数
スキーマは画面に出さないので、描かれない文字も除かない(信頼の境界は登録したこと自体に置く。
`../principles.md`「外部連携の境界を明確にする」)。

操作の記録(`prompt-shape.md`「会話の外での操作の伝え方」)の結果は、1件ごとに直列化したJSONで2,000文字を
上限とし、超えたものは結果を丸ごと省略の注記に置き換える(`llm::prompt`)。記録は以後のターンにも
積もり続けるので、外部ツールの大きな出力や大きなタスクの全体が並ぶと、会話が文脈長に収まらなく
なる。JSONは途中で切ると読めないので切らずに置き換える。何をしたかは`tool`と`arguments`で
伝わり、今の状態はモデルがツールで読み直せる。送るたびに同じ規則で組み立てるので、前に送った
部分は変わらない。

## 置き場所

- 文字単位の部品(描かれない文字の判定、空白の畳み込み、文字数での切り詰め、画面用の
  `display_label`・`display_block`)は `text` に置く。出力先を知らない
- プロンプトの形式に属するもの(予約タグ、ユーザー発言の囲み、その読み方の説明、`PromptText`)は
  `llm::prompt` に置く。タグを変えたときに無害化も追従させるため
