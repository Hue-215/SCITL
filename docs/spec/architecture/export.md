# Markdownエクスポート(Issue #72)

全タスクと総合チャットを1つずつのMarkdownファイルに書き出す(`../principles.md` 1節
「データを特定ソフトに依存させない」)。組み立てと書き込みは
`scitl-core/src/export/` に閉じる。

- **書き出すのは画面から見られるものだけ**。削除したタスク・工程・発言と、会話から外れたターン
  (古い試行・通常発言の残らないターン)は含めない。会話の範囲と並びは画面と同じ取得
  (`db::messages::list_rows_for_chat`)を使い、絞り込みの判断を写さない。思考と
  `error_detail`も含めない(`../data-model/messages.md`)
- ターンの中のツール実行は、返信の項目の中に本文と起きた順で並べる(返信の行の中身。
  `../data-model/messages.md`「1ターン内の往復で保存するもの」)。独立した項目として書くのは、会話に
  並ぶ行である操作の記録だけ
- **書き出し先はcoreの呼び出し側が決め、画面からはパスを受け取らない**。画面から場所を
  指定できると、WebViewを乗っ取られたときに任意の場所へ書かせる経路になる(`attachments.md`の
  「受け取り方」と同じ理由)。デスクトップはデータディレクトリの `export/` に書き、画面はその
  フォルダを開くことだけができる。Androidは利用者が保存画面で選んだ場所へzipで書く(下の
  「Androidでの書き出し先」)。どちらにするかはRust側が決め(`export::ExportTarget::CURRENT`)、
  画面は受け取って、フォルダを開く操作を出すかと結果の文言だけを変える
- **書き出すたびに日時の名前の新しいフォルダを作り、前回までの書き出しには触れない**。
  一時の名前のフォルダに書いてから日時の名前へ移すので、(デスクトップでは)途中で失敗した書き出しは
  完成した書き出しの名前で残らない
- ファイルはタスクごとの `task-<ID>-<タイトル>.md` と `general-chat.md`、メモリの `memories.md`
  (削除したものを除く)。添付は
  `attachments/<添付のID>/<元の名前>` に置き、名前はどのOSでも置ける形にする(`attachments.md`
  「画面での開き方」と同じ規則)。テキストの添付はDBの本文から書き戻す
- 実体を読めない・書けない添付は、リンクの無い項目として書き、書き出し全体は止めない。残りの
  データの持ち出しを優先するため。同梱できなかった数は結果に含めて画面に出す
- 固定文言は英語(`../principles.md` 7節)。日時・MIMEのようにSCITL自身が作る値はそのまま書き、
  無害化は利用者・モデルが決められる値に掛ける(`sanitize.md`の表)

## Androidでの書き出し先

データディレクトリはアプリの内部ストレージにあり(`../data-model/tables.md`「データディレクトリの場所」)、
ほかのアプリからも利用者からも見えず、フォルダを開く手段も無い(`open`クレートが失敗を返す。
`tech-stack.md`「対象のOS」)。そこで**利用者が保存画面で選んだ場所へ、日時の名前のフォルダをzipに
まとめて書く**(`export::export_to_chosen_file`。メンテナの判断、Issue #505)。保存画面で選べるのは
1ファイルだけなのでzipにする。展開した中身はデスクトップの書き出しと同じ形で、添付(「その他」を含む)
も同梱する。デスクトップは中身をすぐ見られるよう、今のフォルダのままにする。

保存先にはGoogleドライブ等の提供元も選べるが、書き込めるかは確かめていない。fsのAndroid側は開いた
ファイル記述子を`ParcelFileDescriptor.detachFd`で切り離してRust側へ渡すので、閉じたときに送り始める
提供元は、書き写す前に閉じられたと扱うおそれがある(Rust側からは見えず、結果は書けたことになる)。
エミュレーターで確かめ、書けなければ端末内への保存を勧める記述に改める。

- **保存画面はRust側が出す**(`tauri-plugin-dialog`。Android側は`ACTION_CREATE_DOCUMENT`)。返った
  `content://`のURIは`tauri-plugin-fs`で書き込み用に開き(`ContentResolver.openAssetFileDescriptor`に
  `wt`を渡す)、その場で書き写すことにだけ使う。どちらのプラグインにも画面の権限(capabilities)を
  与えない。何を書くかは利用者が選ぶので、乗っ取られた画面から呼ばれても、選ばれない限り
  キャッシュの外には何も書かない(添付の選択画面`pick_attachments`と同じ考え方)。保存画面を
  閉じたら何も書かない
- **zipはキャッシュの中で作り終えてから書き写す**(`paths::export_staging`)。選んだファイルは
  保存画面が作った時点で選んだ名前で存在し、書き写すのに失敗しても消す手段が無い(fsのAndroid側は
  開くことしかできず、dialogにも無い。tauri-plugin-fs 2.5.2・tauri-plugin-dialog 2.7.3のソースで確認、
  2026-10)。作り終えてからまとめて書き写すと、書きかけが残る機会は書き写す間だけになる。
  書き写せなかったとき(開く手順のpanicを含む)は、書きかけのファイルが残りうることと消してほしいことを
  画面に出す(`ExportOutcome::LeftIncomplete`)。書き写したら記憶装置へ書き切らせる(パイプで受け取る
  提供元は書き切る操作を持たないので、それは失敗にしない)。zipは成否によらず消す
- フォルダを書き出してからzipにまとめ、zipに入れたファイルはその都度消す。キャッシュに書き出しの
  中身を2つ分載せないため(添付の画像は圧縮が効かず、フォルダとzipでほぼ倍になる)
- 保存画面を出せなかったとき(`tauri-plugin-dialog`はAndroid側の失敗をすべて取りやめとして返す)も、
  取りやめと同じく何も書かず、画面には何も出ない
- 同時に作るzipは1つだけにし、作る前に、強制終了で残った作りかけを片付ける
- 採らなかった案: 共有シート(`ACTION_SEND`。FileProviderとKotlinが要る)、公開の「ダウンロード」
  フォルダ(MediaStore。Kotlinが要り、保存先を選べない)。無圧縮のzipを自前で書く案は、ファイル名の
  符号化と大きさの上限(ZIP64)を自分で持つことになるので採らず、`zip`クレートを使う
  (`tech-stack.md`の表)
