# Markdownエクスポート(Issue #72)

全タスクと総合チャットを1つずつのMarkdownファイルに書き出す(`../principles.md` 1節
「データを特定ソフトに依存させない」、`../legacy/backend.md` 10節)。組み立てと書き込みは
`scitl-core/src/export/` に閉じる。

- **書き出すのは画面から見られるものだけ**。削除したタスク・工程・発言と、会話から外れたターン
  (古い試行・通常発言の残らないターン)は含めない。会話の範囲と並びは画面と同じ取得
  (`db::messages::list_rows_for_chat`)を使い、絞り込みの判断を写さない。思考と
  `error_detail`も含めない(`../data-model/messages.md`)。`../legacy/` は削除済みも印付きで
  含めていたが、再構築では採っていない
- **書き出し先はcoreの呼び出し側が決め、画面からはパスを受け取らない**。画面から場所を
  指定できると、WebViewを乗っ取られたときに任意の場所へ書かせる経路になる(`attachments.md`の
  「受け取り方」と同じ理由)。アプリはデータディレクトリの `export/` に書き、画面はその
  フォルダを開くことだけができる
- **書き出すたびに日時の名前の新しいフォルダを作り、前回までの書き出しには触れない**。
  一時の名前のフォルダに書いてから日時の名前へ移すので、途中で失敗した書き出しは完成した
  書き出しの名前で残らない
- ファイルはタスクごとの `task-<ID>-<タイトル>.md` と `general-chat.md`。添付は
  `attachments/<添付のID>/<元の名前>` に置き、名前はどのOSでも置ける形にする(`attachments.md`
  「画面での開き方」と同じ規則)。テキストの添付はDBの本文から書き戻す
- 実体を読めない・書けない添付は、リンクの無い項目として書き、書き出し全体は止めない。残りの
  データの持ち出しを優先するため。同梱できなかった数は結果に含めて画面に出す
- 固定文言は英語(`../principles.md` 7節)。日時・MIMEのようにSCITL自身が作る値はそのまま書き、
  無害化は利用者・モデルが決められる値に掛ける(`sanitize.md`の表)
