# 縦切り完成までの着手順

マイルストーン「縦切り完成」に入っているIssueを、どの順で着手するかと、その理由を記録する。

**このファイルに書くのは順序と理由だけ**。各Issueが開いているか閉じているかはGitHub Issuesが
正であり、ここには書かない(マージのたびに古くなるため)。順序の前提が変わったとき
(依存が増えた・不要になった等)にだけ更新する。

並べ方の方針は次の3つ。

1. **後続の作り直しを生む土台を先に置く**(設定ファイルの形・履歴の作り方・イベント経路)
2. **安全側の穴を、その穴を広げる機能より先に塞ぐ**(描画のサニタイズ・自由入力の無害化)
3. 同じ層を触るIssueをまとめ、同じコンテキストで連続して片付ける

---

どちらも「Opusを呼ぶ条件」に該当するので、設計判断を先に済ませて土台を固定する。

## 第3段 履歴の寿命を決める

会話が伸びると止まる問題と、ツール結果の扱い。どちらも `build_history` の同じ場所を触るため
連続して行う。添付(第6段)は「トリミングの後に実データを埋める」順序制約があるので、
ここで位置を確保しておく。

| # | 内容 | なぜここか |
|---|---|---|
| #66 | 会話履歴のトリミング(基本方式) | 長い会話がコンテキスト超過で止まる。添付・事実系ツール結果が入る前に基本方式を置く |
| #11 | ツール実行結果の状態系/事実系の分類 | 事実系の結果は履歴を消費するため、#66の直後に入れて対象に含める |
